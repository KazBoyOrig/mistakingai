# Обучи ошибающегося ИИ

Тренажёр понимания процентов: ИИ играет ученика и специально показывает решение с ошибкой. Пользователь находит первый неверный шаг, объясняет причину и решает похожую задачу.

**Интерфейс для демонстрации: главная, тренировка и отдельный экран прогресса.** Основной игровой цикл работает на 15 задачах с восстановлением текущей попытки. Интеграция готовой модели проверяет объяснения по эталонам. Интерфейс явно сообщает: «ИИ специально ошибается. Найди первый неверный шаг».

## Что работает

- По три задачи на каждый тип ошибки: неверная база процента, сложение последовательных изменений, ложная компенсация скидки и равной наценки, путаница процентов с процентными пунктами, неверное восстановление исходного значения.
- Выбор любой задачи, переходы вперёд и назад, две подсказки, открываемые по одной.
- Обязательное объяснение своими словами, проверка выбранного шага кодом, обратная связь. При неверном выборе — повтор и подсказка.
- Полный разбор открывается отдельной кнопкой после проверки; только затем появляется похожая задача.
- Оценка объяснения моделью: верно, частично верно, неверно или неоднозначно. Для частичного/неоднозначного ответа — один уточняющий вопрос и возможность дополнить объяснение. Короткие ответы допустимы.
- Похожая задача с однозначным числовым ответом и единицей (₽, %, п.п.); число проверяет сервер. Допустимы запятая, точка, пробелы, «рублей», «процентов» и «процентных пунктов»; неверная единица отклоняется.
- До 100 попыток в localStorage с отдельными результатами шага, объяснения и закрепления; история по задачам, повтор попытки и сброс всей истории с подтверждением.
- Текущая задача, выбранный шаг, объяснение, подсказки, обратная связь, открытый разбор и ответ восстанавливаются после обновления страницы. При уточнении вопрос ИИ остаётся над полем ввода и также восстанавливается.
- Русский адаптивный интерфейс, загрузка, ошибки, управление с клавиатуры.

Для смысловой проверки нужен серверный API-ключ. Без ключа, при тайм-ауте, отказе модели или сбое API приложение показывает **«Объяснение не оценено»**; проверенный разбор остаётся доступен по кнопке. Временный сбой можно повторить до завершения попытки. Неверное объяснение не мешает открыть разбор. Оценка модели сохраняется в прогрессе; старые попытки остаются совместимыми. На экране прогресса три результата каждой последней попытки показаны отдельно.

## Показ жюри

Готовые питч на 30 секунд, сценарий на 2 минуты и план проверки учебной пользы — в [DEMO.md](DEMO.md). Итоги финальной проверки и реально использованные тексты объяснений — в [FINAL_CHECK.md](FINAL_CHECK.md).

На главной коротко объясняется механика. В блоке «Для показа жюри» выберите задачу и нажмите **«Начать демо»**: начнётся новая попытка, история сохранится. По умолчанию выбран рюкзак: скидка 20%, затем наценка 20%. Первый неверный шаг — 3; правильная цена — 1920 ₽; ответ закрепления — 990 ₽.

Прямая ссылка на выбранный пример находится рядом с кнопкой. Для стандартного демо: **http://127.0.0.1:5173/?demo=discount-then-markup-01#training** (после сборки с `npm start` замените порт на 3001). Можно подставить другой ID из банка. Обновление этой ссылки восстанавливает текущую попытку; для чистого показа используйте «Начать демо» или «Пройти ещё раз».

Светлый интерфейс адаптируется к компьютеру и узкому экрану. Бип, небольшой ИИ-ученик, нарисован CSS. После отправки форма сворачивается, чтобы освободить место для обратной связи; она остаётся доступна по кнопке «Показать задачу и моё объяснение». Итог показывает «Нашёл ошибочный шаг», «Объяснил причину», «Решил похожую задачу» с независимыми статусами, включая «Не оценено». Экран прогресса показывает число задач с верным закреплением, число попыток и верных объяснений; по каждой задаче видна последняя попытка.

## Запуск

Node.js **22.12 или новее** (рекомендуется Node.js 24 LTS), npm.

```bash
git clone https://github.com/KazBoyOrig/mistakingai.git
cd mistakingai
npm ci
npm run dev
```

Открыть **http://127.0.0.1:5173**. Одна команда запускает Vite и сервер Node.js на 127.0.0.1:3001. Запросы /api идут через прокси Vite. Без ключа работает цикл с самостоятельным сравнением объяснения с эталоном.

Если Windows PowerShell блокирует npm.ps1, используйте `npm.cmd ci` и `npm.cmd run dev`.

## Проверки и сборка

```bash
npm run check
npm start
```

`check` запускает 41 тест: структура банка, 30 расчётов, числовой парсер и единицы, HTTP API, четыре вердикта и формат вопроса, сбои/тайм-ауты модели, объединение повторных запросов, совместимость прогресса, независимость трёх результатов, восстановление этапов игры и уточняющего вопроса, сброс с отказами хранилища; затем проверяет типы TypeScript и сборку Vite. Тесты используют контролируемые ответы провайдера, ключ и API-кредиты не нужны. GitHub Actions запускает ту же проверку. После сборки `npm start` отдаёт интерфейс и API на **http://127.0.0.1:3001**. Остановка — Ctrl+C. Перед `npm start` остановите `npm run dev`, поскольку оба режима используют порт 3001. Отдельные команды: `npm test`, `npm run typecheck`, `npm run build`, `npm run dev:client`, `npm run dev:server`.

Интерфейс проверен в браузере при 1280×900, 390×844 и 320×740: старт, выбор демо и прямая ссылка, неверный шаг → подсказка → повтор, разбор, неверная единица, числовые ответы с пробелами/запятой, итог, прогресс, повтор и переходы. Черновик, обратная связь, открытый разбор и итог проверены после обновления страницы. На всех трёх экранах при ширине 320 пикселей горизонтальной прокрутки нет; переход к содержимому работает с клавиатуры. Частичное объяснение → уточняющий вопрос → верное объяснение → закрепление проверены с контролируемым ответом провайдера на отдельном тестовом сервере. Настоящая модель без API-ключа не вызывалась; в приложении объяснение остаётся неоценённым.

## Подключение проверки объяснений

Скопируйте `.env.example` в `.env`, заполните OPENAI_API_KEY **локально** и перезапустите сервер:

```dotenv
HOST=127.0.0.1
PORT=3001
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4o-mini
```

Ключ остаётся только на сервере; `.env` исключён из Git. Не помещайте ключ в исходники или переменные VITE_. По умолчанию используется gpt-4o-mini; OPENAI_MODEL позволяет выбрать другую доступную модель с поддержкой Responses API и Structured Outputs. Наличие ключа не гарантирует доступ к модели и средства на API-счёте. При изменении PORT в разработке также измените прокси в vite.config.ts.

Клиент отправляет идентификатор задачи, выбранный шаг и объяснение. Условие, ошибочное решение, выбранный шаг, проверенное правильное решение, эталонное объяснение и рубрику сервер берёт из банка и передаёт модели как проверенный контекст в системном сообщении. Объяснение пользователя — отдельно как данные JSON. Промпт требует оценивать математическую причину, принимать разные формулировки и короткие ответы; указание номера шага или результата без причины не засчитывается. Команды внутри объяснения не являются инструкциями проверяющему.

Модель возвращает строго три поля:

```json
{
  "verdict": "partial",
  "feedback": "Ты заметил изменение цены, но нужно уточнить базу наценки.",
  "followUpQuestion": "От какой цены берутся следующие 20%?"
}
```

`verdict`: correct | partial | incorrect | unclear. correct означает понятную верную причину, partial — верный фрагмент без полного объяснения, incorrect — неверную причину или только шаг/результат, unclear — неоднозначный текст. `followUpQuestion` обязателен для partial/unclear, для correct/incorrect равен null. Structured Outputs задаёт JSON Schema; Zod на сервере дополнительно проверяет точные поля, типы, непустую обратную связь до 500 символов и один вопрос до 240 символов с единственным «?» в конце. Некорректный ответ не превращается в оценку. Модель не изменяет номер шага, числовой ответ или эталон.

Запрос ограничен 20 секундами; до трёх разных одновременных проверок, без автоматических повторов. Кнопка блокируется во время запроса; одновременно пришедшие одинаковые задача/шаг/объяснение объединяются на сервере. После завершения повтор по кнопке вызывает новую проверку, результаты не кэшируются сервером. Передаётся store:false, ответ не используется как история беседы. Ключ, пользовательский текст и сырой ответ провайдера не записываются в журналы приложения. Это локальный MVP; публичный сервер потребует контроля доступа и расходов API.

### Проверка настоящей модели

35 примеров в `server/explanation-cases.ts` покрывают четыре вердикта и попытки сменить инструкции для всех пяти типов ошибок. Для каждого типа есть три разные верные формулировки: развёрнутая, короткая и с формулой. У части верных объяснений намеренно выбран неверный шаг, чтобы проверить независимость оценок. При настроенном ключе:

```bash
npm run eval:model
# Или один пример:
npm run eval:model -- cancel-correct
```

Команда вызывает настоящую модель, расходует API-кредиты и сравнивает оценки с ожидаемыми. При несовпадении, неоценённом объяснении или отсутствии ключа она завершается с ошибкой. Без ключа запросов нет. Команда не входит в обычные тесты и CI. Успешные тесты транспорта не доказывают качество смысловой проверки. При реализации ключ не был настроен, поэтому живой прогон ещё не выполнен.

## Формат банка

`server/exercises.json` — массив из 15 объектов. Каждая запись содержит:

- id, title, errorType, topic, difficulty, prompt;
- steps: объекты number, title, text; 3–5 шагов подряд, нумерация начинается с 1;
- firstWrongStep, correctSteps, correctAnswer, answerUnit, errorExplanation;
- hints: ровно две разные подсказки; rubric: критерии оценки объяснения;
- calculation: числовые исходные данные и операция для основного ответа;
- practice: prompt, unit, answer, explanation, calculation.

Типы ошибок: wrong-base, sum-sequential, equal-cancel, percentage-points, reverse-value — по три задачи каждого типа.

Расчёты отделены от текста: sequential применяет изменения по порядку, relative-change считает относительный рост, percentage-points — прямую разность долей, reverse-change восстанавливает цену до изменения, reverse-part — целое по известной части. Валидатор Zod при старте проверяет структуру, уникальность ID, номера шагов, подсказки, единицы и все 30 ответов. Ошибочный банк не запускается. Тесты дополнительно проверяют независимые контрольные ответы и намеренно повреждённые записи. Верность шагов до ошибки и логика последующих шагов проверены при подготовке содержания; тесты не подменяют текстовую проверку арифметической.

## Проверка вручную

1. В задаче 1 выберите шаг 1 и напишите объяснение. Откройте первую подсказку, обновите страницу: выбранный шаг, текст и подсказка должны восстановиться.
2. Нажмите «Проверить шаг и объяснение». Неверный выбор предлагает повтор и подсказку, полный разбор ещё скрыт. Обновите страницу: обратная связь остаётся, история не дублируется.
3. Нажмите «Попробовать снова», выберите шаг 3 и объясните, что наценка считается от новой цены. Текст и подсказки при повторе сохраняются. Откройте разбор отдельной кнопкой: итог — 1920 ₽.
4. В закреплении введите «990,00 рублей» и обновите страницу до проверки: разбор и ответ остаются открыты. Проверьте ответ и обновите страницу ещё раз: три результата и подтверждение сохранения остаются, число попыток не увеличивается.
5. В задаче 10 «Доля сбережений» выберите шаг 2 и объясните разницу между процентами и процентными пунктами. После открытия разбора ответ «12%» должен отклоняться; «12 процентных пунктов» принимается.
6. Неверный числовой ответ завершает попытку с отдельным результатом «Закрепление: неверно». Попробуйте пустое объяснение, формулу вместо числа и повтор через «Пройти ещё раз».
7. Переключите задачу кнопками или списком: форма сбросится, история останется. После обновления страницы останется последняя выбранная задача.
8. С ключом сравните три верные формулировки из контрольных примеров, частичное объяснение, «Одинаковые проценты всегда компенсируются» и неоднозначный ответ. Для partial/unclear должен появиться один вопрос; нажмите «Уточнить объяснение», дополните текст и отправьте снова. Выбранный шаг проверяется отдельно. Без ключа статус должен быть «Объяснение не оценено», разбор и закрепление остаются доступны.

Прогресс относится к конкретному браузеру и адресу: localhost, 127.0.0.1 и разные порты имеют отдельные хранилища. История (`mistakingai.attempts.v1`) записывается сразу после проверки объяснения: закрепление пока имеет `practiceCorrect: null`. Проверка числа обновляет ту же запись; повтор выбора или полное повторение создаёт новую попытку. Повтор временного сбоя модели обновляет прежнюю запись. Три результата не подменяют друг друга: неверный шаг может сочетаться с верным числом.

Текущая форма и этап хранятся отдельно (`mistakingai.session.v1`), проверяются схемой при загрузке и восстанавливаются без повторного запроса к модели. Смена задачи или «Пройти ещё раз» сбрасывает форму. На экране прогресса «Сбросить прогресс» открывает подтверждение: отмена сохраняет данные, подтверждение удаляет историю и текущую попытку только этого приложения. При отказе хранилища приложение сообщает о проблеме и не выдаёт сброс за успешный; данные на экране сохраняются, откат хранилища выполняется по возможности. Очистка данных сайта также удаляет прогресс. При недоступном или повреждённом хранилище приложение продолжает работу; повреждённая форма не удаляет историю.

## Структура и API

- src/ — интерфейс, API-клиент, локальная история (storage.ts) и текущая попытка (session.ts).
- shared/types.ts — контракты клиента и сервера.
- server/exercises.json — банк заданий.
- server/exercise-bank.ts — схема данных и вычисления.
- server/exercises.ts — проверка шага и числового ответа.
- server/explanation-evaluator.ts — интеграция с моделью и валидация результата.
- server/explanation-cases.ts, evaluate-model.ts — контрольные примеры и живой прогон.
- server/app.ts, server/index.ts — HTTP API, статика и запуск.
- server/*.test.ts — контрольные расчёты, API, провайдер и локальный прогресс.
- SPEC.md — описание полного MVP и этапов.
- DEMO.md — питч, сценарий показа и способ проверить учебную пользу.
- FINAL_CHECK.md — проверенные расчёты, примеры объяснений, результаты и ограничения финальной проверки.

API: GET /api/health, GET /api/exercises, GET /api/exercises/:id, POST /api/review (exerciseId, selectedStep, explanation), GET /api/solutions/:id, POST /api/practice (exerciseId, answer). GET /api/exercises/demo остаётся псевдонимом первой задачи. Список, отдельная задача и Review не раскрывают полный разбор, номер ошибки или числовые ответы. Разбор запрашивается отдельным GET после нажатия кнопки; ответ закрепления не входит в Solution. Решения ИИ заранее подготовлены. Это разделение этапов интерфейса, а не ограничение доступа к учебным материалам.

Health возвращает mode:model или reference_only — наличие настроенного ключа. Review содержит `selectedStepCorrect`, `stepFeedback`, `verdict`, `feedback`, `followUpQuestion`, `explanationIssue`. При сбое модели HTTP 200, `verdict: null` и причина; это отсутствие автоматической оценки, а не unclear. Локальная история сохраняет такой результат как not_evaluated. Ошибочный ввод — HTTP 400. Solution содержит первый неверный шаг, эталон, правильные шаги, итог и условие закрепления с единицей. Старые записи прогресса и экран с оценкой по рубрике остаются совместимыми; новые записи сохраняют уточняющий вопрос.
